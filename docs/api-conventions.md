# 接口规范

## 1. URL 规范

- 基础路径建议：`/api/<domain>`
- 资源命名使用名词，不使用动词
- 严格遵守 HTTP 语义（`GET/POST/PUT/DELETE`）

## 2. 请求与响应规范

- 入参模型：`dto.request.*`
- 出参统一外层：`Result<T>`
- 优先使用 `VO` 作为 `T` 的数据模型
- 仅在复合返回场景使用 `dto.response.*`

## 3. 统一响应示例

```json
{
  "code": "0",
  "message": "success",
  "data": {},
  "traceId": "..."
}
```

## 4. 分页规范

- 请求参数：`pageNum`、`pageSize`
- 返回参数：`total`、`list`

## 5. 错误处理规范

- 使用稳定且可追踪的业务错误码体系
- 不向前端暴露原始堆栈信息
- 参数校验失败返回可读的字段级错误信息

## 6. 兼容性规范

- 优先采用向后兼容的增量变更（新增字段）
- 非版本升级场景不删除/重命名既有字段
- 破坏性变更必须显式升级版本（如 `/v2/...`）
